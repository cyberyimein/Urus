## 1. 第一性原则：帮助用户在仍值得买的时点做出买入决定

系统的主要产品是一次有依据、来得及执行、知道何时退出的买入决定。指标、数据库、AI和回测只有在帮助改善这个决定时才值得建设。

核心问题：

> 在这条提醒实际到达用户、用户有时间处理之后，以当时可以买到的价格买入，按事先明确的退出政策管理，是否有成本后正期望；它是否比简单替代选择更值得占用资金？

“赚钱”必须落实为完整交易结果；后面曾经上涨、最高涨幅很大、提醒当天看多都不等于用户赚到了钱。正期望也不等于每笔盈利。

### 1.1 一次机会必须回答的六个问题

1. 为什么是这个标的：存在什么可检验的需求/价格行为假设？
2. 为什么是现在：刚发生了什么，而非只是仍处于强势？
3. 买多少钱的价格：当前可接受区间、最高买价、超过之后怎么办？
4. 判断错了怎么办：初始风险、跳空风险、失效和退出方式？
5. 凭什么值得买：同一政策历史净收益、样本外支持、反证和适用范围？
6. 用户来得及吗：收到后5/15/30分钟的结果，以及当前是否已经失效？

不输出由指标票数制造的胜率。不为每天凑足机会数量而推荐。系统无合格机会时应明确空缺；有少数大机会时要能及时保留和跟踪，不能为了“收益均匀”把它们过滤掉。

### 1.2 产品边界与默认用户模式

仍是研究与人工决策辅助，不连接券商下单。可记录用户自愿输入的模拟/实际成交，但必须区分来源，不能把模拟结果叫用户实际收益。

默认模式：提前给计划，盘中偶尔处理提醒；不假定用户一直盯盘或能秒级下单。用户可选择快速响应/常规响应/只在固定窗口处理。首版研究主响应延迟为15分钟，同时报告1/5/30分钟对照；这是待验证的使用假设，不是关于用户的既定事实。

用户操作窗口以交易所时间配置并转换到本地时区。初始常规观察窗口为美东09:45–15:15；未配置可用窗口时不宣称提醒适合用户。当前方案不创建定时任务或对外发送消息；实施时先在应用内记录提醒生成与投递，其他渠道另行明确授权。

首批为美股股票与普通股票ETF现金多头，目标持有数日至20个交易日。杠杆/反向ETF、期权交易、裸空和自动加仓不进入首期。允许的Universe沿用现有授权范围；是否需要扩大研究池由覆盖结果决定。

## 2. 如何判定系统有用

### 2.1 主要目标、反事实与约束

主目标：在冻结的使用时间、响应延迟、成交成本、退出政策和资金约束下，提醒驱动的模拟组合取得正的成本后结果；进一步证明筛选或时机相对简单替代增加了什么价值。盈利可实现性与额外选时优势分别给结论，不混为一种资格。

需要同时回答：

- **绝对价值**：净期望、收益分布及现金机会成本；不能只是比亏损基线少亏一点就推荐买入。
- **新增价值**：相同可执行条件下，筛选/提醒是否优于简单规则或基准持有？
- **可实现性**：用户可用的响应速度下仍成立，且不是利用当日收盘或已知开盘价倒填成交。
- **代价**：回撤、跳空、资金占用、重复暴露、无效提醒与错失机会。
- **范围**：结论仅适用于已研究Universe、资产类型、数据覆盖和市场环境。

买入系统与风险防御工具分别评估。减少亏损可以是有效风险信息，但不能冒充有盈利依据的新开仓机会。

### 2.2 不能只评价入选样本

保存“已授权Universe中的每次扫描”，包含入选、被拒、未覆盖、流动性不足、事件未知、价格已跑远等原因。每增加一个过滤器，必须同时报告：

- 去掉了多少后续亏损机会；
- 错过了多少后续盈利机会及其收益贡献；
- 提醒数量和用户处理成本怎样变化；
- 在相同模拟资金约束下净结果如何变化。

仅对入选样本计算胜率，会奖励“极少提醒、漏掉大部分机会”的系统。历史上未采集的分钟数据不能补成已知；数据缺失导致的漏报与规则拒绝导致的漏报分开。

### 2.3 评估链条

```text
授权研究池 -> 可观察标的 -> 形成中的结构 -> 首次触发
          -> 提醒生成/送达 -> 用户响应 -> 买入前复核
          -> 模拟或用户记录的成交 -> 退出管理 -> 净结果
```

每一步记录数量、时间和未继续原因。系统发现很早但用户收到很晚，不能算成功；发现正确但全部成交假设不现实，也不能算成功。

## 3. 首期范围：先做一条能评价的闭环

第一版只研究一类简单突破机会S1，并用同一退出和成交规则比较少量背景过滤变体。选择它是因为触发事件易定义、现有OHLCV可支持，不代表已经认定突破最赚钱。

日线用于提前准备结构；15分钟用于候选触发；报价用于用户响应后的买入复核。频率围绕能否及时指导用户选择。日级回放和盘中回放分级实现，不要求先完成完整平台才能检验假设。

### 3.1 必须先做

- 修正当前明确的误确认/误合成问题。
- 现有数据覆盖清点、价格口径与可见性规则。
- S1最小检测器、扫描记录、独立触发事件、提醒计划。
- 用户延迟与明确成交/退出政策。
- 成本后结果、简单基线与漏报对照。
- 一份端到端离线实验结果；数据不够时提供真实coverage与可运行fixture，明确未证明有效。

### 3.2 首期不做

- 两类以上策略同时扩张。
- 条件收益预测模型、复杂效用总分、相关性图优化。
- 一开始新增十余张领域表和全套REST API。
- 独立事件交易策略、期权交易结构和新AI仲裁平台。
- 为规则没有收益贡献的问题换一个更复杂的模型包装。

第二种入场方式只有在有明确问题时才加入：例如S1有效但经常因价格跑远错过，才单独研究回踩再入；日级模式因反应太晚失去收益，才研究更早的盘中触发，不默认越快越好。

## 5. 证据与时间：按事实类型定义

### 5.1 通用知识时间

`available_at`表示这条revision实际可供系统使用的时间，原则上不早于source published/received time。决策只能读available_at<=decision_knowledge_time的版本。

| 事实类型 | 适用过滤 |
|---|---|
| 已完成bar | bar_end<=market_cutoff；received_at<=knowledge_cutoff；bar完整 |
| 实时报价 | quote_time<=当前市场时刻；received_at<=knowledge_cutoff；通过年龄/双边质量门 |
| 未来日历 | published_at/received_at<=knowledge_cutoff；scheduled_for可晚于当前时间 |
| 已发布事件内容 | released_at/received_at<=knowledge_cutoff；不得读取之后修订 |
| 修订历史事实 | 只能在新知识时点用于新评价，旧Bundle不变 |

迟到信息要更新当前认识。例如10:35收到10:20公告，即在10:35重新评价风险；不得因其事件时间早于10:30行情head而只送历史分支。

区分两条输入：旧bar的乱序回放不回退行情游标；新知识导致的重新评价不需要行情时间前进。evaluation以知识时间和证据hash排序，不能只按bar_end拒绝新评价。新的事件知识不会创造新的价格穿越。

### 5.2 历史模式

- `observed_pit`：真实保存的当时可见revision及接收时间。
- `historical_reconstruction`：后来下载历史行情；保存来源与修订限制，采用预注册的可用时间/延迟假设，不能宣称当时系统实际已知。
- `daily_execution_proxy`：只有日线的简化成交研究；不得证明盘中提醒的用户可实现性。

使用现有分钟revision表做历史选择，不读会更新的latest bar表重放历史。日期、交易所日历、时段、bar起止、DST与提前收盘明确；15分钟桶从常规开盘锚定，缺分钟或不完整桶不触发。

### 5.3 价格与质量

指标必须同一adjustment basis；执行必须当时可交易的未复权报价。保存因子版本；无映射不混算QFQ与原始分钟价。拆股对结构价位和模拟股数做可审计单位换算，分红进入收益现金流；无法处理则标该样本受限，不悄悄剔除亏损。

初始在线SLA：quote_age<=60秒、触发bar收到不晚于bar_end后120秒。迟到仍可记录市场事件，但标late_discovery，不声称及时买点。没有双边quote可继续记录结构，不能出当前可买标记。

质量、策略成立、研究证据和用户可操作性为四个独立字段，不压成一个status。任一未通过会阻止“当前可考虑买入”，但保留事实、反证和观察机会。

## 6. 探测面与候选结构

### 6.1 研究池

使用当时冻结的已授权Universe；当前人工watchlist只能支持“在该池内”的结论，不宣称全市场选股。每次扫描保存pool_version、实际覆盖、拒绝原因及benchmark_mapping。

基础可研究资格：至少61根有效日线、close>=5美元、前20日中位原始成交额>=2000万美元。阈值是初始可交易性约束；数据不足、资产类型不适用和未采集分开。不能为获得61/200根数据自动扩大请求范围。

行业、市场基准先做背景字段。S1基础实验不把MA50排列、RSI、相对收益、量能全部设为门。行业不可用返回null；不自动以QQQ填成行业比较。

### 6.2 两级观察，显式统计覆盖限制

收市时扫描整个授权研究池。候选分钟采集可以优先给距结构位<=1 ATR的标的，但这只是一项采集预算政策，不是alpha条件。其余标的每日仍保留扫描记录；有已授权批量quote能力时，发现接近结构位可提升观察优先级。

没有当时分钟数据的突然突破记coverage_miss，不冒充strategy_reject。报告“数据范围内召回率”和“可观察范围占研究池比例”；不能从候选子集算出漂亮胜率后宣称发现能力很强。

## 7. S1：简单结构突破与一个明确的交易假设

假设：价格突破此前整理区高点后，有一部分机会会持续上涨；系统能否用当时可见背景和可接受入场价格筛出其中有正净期望的一部分。

### 7.1 收市准备

在完整交易日D的数据可见后，计算下一session起可用的结构：

```text
A = 最近14个完整日TR的简单平均（沿用atr14_sma_tr_v1）
L = D及此前共20根日bar的最高价
S = D及此前共5根日bar的最低价 - 0.25*A
U = L + 0.50*A
```

可用结构要求0.5<=(L-S)/A<=3、A>0及基础流动性通过。下限用于避免异常/极小风险距离，上限限制结构风险；它们仍要报告筛掉的机会，不能称最优。

结构首次发布时冻结L/S/A/U及来源。等待从下一session计第1天，最多5个session，最后一天收盘前仍可触发；收盘边界处理完再到期。不因每日滚动高点自动移动同一个结构。结构更新与新机会身份见第8节。

此时提示“接近什么条件”，不是买入建议。可研究特征并列保存：MA50位置/斜率、20日市场超额收益、收缩比例、量比、行业背景、近期事件；基础S1不以这些字段叠加成总分。

### 7.2 首次触发

主执行模式的价格事件：

```text
previous_completed_close <= L
current_completed_15m_close > L
```

第一根常规15分钟bar以昨日常规close作previous值。跳空站上L也可形成open_gap_cross，必须单独记录，不与连续盘中穿越混淆。

当前bar close>U时，记录真实穿越，但entry_opportunity=missed_extension；不能让“超过上限”消灭触发事实。等待期间bar low<=S则结构失效；若同一完整close触发bar此前已经low<=S，先判结构失效，不能选择有利路径。

如果系统开始观察时价格已经在L上方，但没有见到当时穿越，记录late_discovery，不合成fresh_trigger。后续“仍在L上方”不再触发。数据断档跨越L记cross_unobserved，不补造精确事件时间。

daily对照使用前一完整日close<=L且当前日close>L；在实际完整日bar可用后才发现，后续执行按第9节。不能用日级触发的入选集合筛选盘中成功案例。

### 7.3 买入计划和退出

计划区间为[L,U]；初始结构stop为S。计划在提醒送达后45分钟内有效，并且不跨越当日15:45；若届时用户未响应，关闭本次entry intent。45分钟是首版使用政策，为30分钟响应对照留出执行时间；必须检验15/30分钟响应后的收益，不能凭界面可显示就声称有效。

买入前复核报价、事件、结构、剩余时间和研究资格。上涨超过U后本次提醒取消；之后回落不得对同一提醒挑选更好的回测fill。新的真实回踩机会是独立研究问题。

主要退出政策固定为：
- 入场后初始保护stop S；不因市场下跌扩大stop。
- 持有中的完整日close<L，形成结构失败退出意图，在下一配置操作窗口按其后报价执行。
- 最多持有20个session（fill日为1）；第20日收市生成退出意图，下一可执行窗口退出。
- 无固定盈利目标、无分批、无追踪stop。这样不会先把少数延续性大机会人为截断。
- 停牌/跳空可能使损失超过初始R。观察后曾涨到+2R不算获利，必须按退出政策计算。

未来“跟随趋势持有”或“回踩再买”只各作为一个独立变体；不得在每笔历史交易上挑最赚钱的退出方式。

## 8. 结构、触发、入场与标签分离

四个独立对象：

| 对象 | 寿命/作用 |
|---|---|
| setup | 冻结的结构假设：armed/resolved/invalidated/expired |
| trigger | 一次已观察到的穿越：不可变事实 |
| entry_intent | 对该trigger的一次提醒与买入计划：pending/ready/submitted/filled/cancelled/expired |
| outcome_job | 未来标签任务：pending/mature/censored；没有阻止新机会的权力 |

setup发生首次trigger后resolved，不再持有“等待20日标签”状态。entry_intent的超时、未成交不影响trigger的后续结果记录。

同一标的/族/结构指纹只允许一个待触发setup；同一trigger只允许一个entry intent。不设“该标的20日内只能有一个机会”的全局约束。

结构指纹：
`hash(symbol, family_version, parameter_hash, benchmark_mapping, trigger_timeframe, anchor_pivot_bar_id, base_start_bar_id, L, S, price_basis, stream_id)`。
滚动扫描日和组ID不进入结构身份；只改变接收时间不能创建新结构。

新结构资格：前一个setup resolved/invalidated/expired之后，至少形成3根新的完整日bar；新的最高价锚或五日base起点必须包含前一setup关闭后的bar，且当前close<=新L。若只是相同锚反复被扫描，复用旧身份，不制造fresh signal。3日是结构重建政策，单独测漏报，不能随标签完成时间伸缩。

不同组只是关联；online与每次实验使用不同stream。正在计算旧标签时，新结构可以触发。模拟组合若已经持有同一symbol，不自动再加仓；记录position_constraint，并继续记录新信号的独立机会结果。

## 9. 用户能实现的买入流程与成交模型

### 9.1 明确区分看见、决定与成交

`signal_known_at -> alert_created_at -> alert_delivered_at -> user_ready_at -> recheck_at -> intent_sent_at -> fill_at`。

模拟用户延迟从delivered_at开始，不从K线结束开始。缺少真实投递时间时使用模拟服务延迟并标simulated_delivery。提醒投递失败不算用户看到。默认15分钟响应；快速模式能赚钱但15分钟已经失效的策略，应标“仅适合快速响应”，不能推荐给默认模式。

### 9.2 主报价执行政策 Q1

1. user_ready_at之后取第一条合格双边报价Q0；不得挑一个更有利的后续报价作决策。
2. 若ask不在[L,U]、结构/事件/时间不符，取消entry intent，写明原因。
3. 根据Q0和预先输入的paper预算计算数量，冻结最高买价U；尚未知道fill时不得用fill倒算完美风险股数。
4. 模拟一笔有明确限价U的买入意图。经注册的执行延迟（初始1秒）后，取第一条合格报价Q1；最多等待60秒，需quote timestamp/received时间一致。
5. 若Q1.ask<=U，保守模拟成交在Q1.ask加已注册滑点且不高于U；超U则不成交，不将滑点结果截断到U。真实成交只有broker/user确认可证明；无深度的小额quote fill仍标quote_proxy。
6. Q1.ask低于L但高于S时，按可实际发生的价格改善成交并记录breach_during_latency；不能事后撤销已发送买入意图。若已低于S，记录fill与立即风险退出的可能不利结果，不能把危险路径删成not_filled。
7. Q1时限内未成交则关闭本次意图，不在一天里反复找好价。取消与成交竞态无逐笔证据时保守标execution_ambiguous，报告边界，不假装零损失取消。

普通买入限价限定最高价，不提供“低于下限自动拒绝”的保证；最后成交价也不等于可买报价。执行边界依据[Investor.gov订单说明](https://www.investor.gov/introduction-investing/investing-basics/how-stock-markets-work/types-orders)，上述Q1具体模拟规则是项目假设，需与实际人工操作比较。

有真实成交记录时保留原始输入，不用paper fill覆盖。实际partial fill单独记录；没有深度时不能宣称大额全量可成交。

### 9.3 只有分钟/日线时

分钟代理M1：user_ready_at之后第一根完整1分钟bar结束后，以其close作为观察价进行区间检查；模拟意图只能作用于再下一根bar的open。买入上限仍约束，低于L的开盘不能事后拒绝；stop路径和价格改善按既定代理记录。该模式不证明spread、排队和真正fill，需Q1 shadow验证。

日线代理D1：完整日信号可见后，在下一交易日开盘前决定是否提交最高价U的限价意图；以该日open模拟：open<=U则允许成交，包括open<L，计入不利gap和stop。不得先检查未来open>=L再决定参与开盘。没有实际委托时只作execution_proxy对照。

D1是提前计划政策，Q1是观察后行动政策，分别计分，不能拼成一条策略挑各自优点。日线不足以验证15分钟响应，禁止把D1盈利直接当默认提醒模式有效。

### 9.4 费用、风险与退出可实现性

- 有bid/ask：买ask、卖bid，加独立滑点与实际可用费用表；未知费用标proxy。
- OHLC代理：每边5/10/20bps为包含spread/滑点/费用的all-in敏感性，不再次扣同一费用。主档10bps预先注册。
- 多头stop：gap穿过S以之后可卖价格处理，不能截为-1R。只有OHLC时，用较差open或stop减成本并标近似。
- 日close失败/时间退出按下一用户操作窗口、用户响应延迟及之后的卖价模拟，不能在此前close退出。
- 首批paper基础假设为用户入场时设置保护stop；stop是外部用户行为假设，系统不发订单。未设置stop的用户必须看manual_exit模式结果；不能用自动stop回测指导纯手动用户却不披露。
- 用户可操作性设置影响入场和退出两端。没有交易时段/退出能力信息时不生成真实股数建议。

## 10. 事件和背景：先防信息错误，再检验收益贡献

不把未知事件当成无事件。最小字段为event_id/revision、symbol或market、scheduled_for、released_at、published_at、received_at、source、coverage_window/status。

首期实现fixture与可审计人工导入。正式来源接入以可访问性、许可和覆盖实测决定，不假设现在已有财报预期订阅。

两类门分开：
- 可靠性门：时间错误、价格过期、关键事件覆盖未知等，阻止当前可买标记。
- 经济过滤：市场趋势、行业强弱、量能、事件前后窗口是否让收益更好，必须有对照，不凭叙事全部设成买入前提。

初始普通技术政策E0：
- 财报在未来2个session内，不发新增普通技术买入建议；发布后首根完整常规日bar形成之前暂停。日期不精确按整session覆盖。
- 已确认重大公司公告，收到后立即重新评价并暂停至下一完整日bar；旧机会事实保留。
- CPI/就业/FOMC的实际响应/入场窗口若处于发布前30分钟至发布后30分钟，则取消本次entry intent；延期不明保持unknown。
- 事件查询覆盖未来20个session，并单独输出“预计持有期将跨事件”。2日禁入不代表20日持有已经避开财报。
- 主要S1可跨较远事件持有，作为明确风险假设；“财报前退出”只作独立政策变体，不能根据事后涨跌选择。
- 取消或延期的日历新revision更新当前资格，不将普通价格结构误判为已失效。

ETF不要求自己的公司财报日历；公司级和市场级coverage按资产适用，不能因ETF不存在财报而永久unknown。sector benchmark缺失只影响需要它的实验，不阻止所有基础策略。

初始消融最多两个：S1+市场趋势条件（基准close>MA50）、S1+20日相对基准表现>0；各自与S1单独比较，暂不叠加成第三个组合。不先引入成交量、RSI、MACD或布林带硬门。

## 11. 从研究线索到对用户的买入指导

### 11.1 产品状态

- **准备**：结构存在，明确“什么发生后值得重新看”。
- **触发待验证**：发生穿越，策略或操作模式尚无足够证据，不称为已验证买点。
- **当前可考虑买入**：价格/数据/事件/用户可用性通过，且对应策略、执行模式和适用范围获得收益支持。
- **错过/取消/失效**：清楚说明为什么不再买，不把旧提醒继续置顶。
- **持有管理**：仅针对用户声明或paper持有，给对应退出与风险；不假定用户已买。

一次提醒内容必须包括：symbol、触发事实与发生/获知时间、可买区间/最高价、stop与gap说明、计划持有/退出政策、持有期事件、证据等级/样本、当前反证、刷新/到期时间。

“为什么买”优先使用交易假设和增量证据，而非指标清单。如“刚越过冻结结构，当前仍在已研究入场范围；该政策在15分钟响应模式下净期望为……”。没有研究数值时明确无可用估计，不让LLM编造。

### 11.2 排序与提醒预算

展示顺序与paper资金分配分开命名和版本化。第一版不输出预期收益总排名。

准备队列按距离L/ATR排序；触发队列只保留仍有效且符合用户时间窗的候选，按首次delivered_at升序处理，symbol稳定打破同时刻平局。FIFO是明确可实施的服务基线，不称“最优”。

初始最多同时展示3个待处理入场提醒；额外候选仍记录suppressed_by_attention_budget并计算结果。用户可调预算，但每种预算是独立使用政策。不同风险提醒不占这3个买入名额。实际发送过的提醒不会因为后来出现更好候选而从历史删除。

后续是否采用相对强弱排序或更少提醒，用相同资金/延迟预算对照FIFO；至少证明更高的成本后净价值或更低处理负担，才替换。相近候选没有统计区分时并列，不装作能精确挑出第一名。

### 11.3 简单paper资金政策

用于评价，非用户实盘建议：每个fill前计划风险0.25% NAV、单symbol名义<=20% NAV、总多头名义<=100%、最多3个并发symbol、总初始风险<=0.75% NAV。数量以发送前Q0及S计算，再受现金/名义限制；成交变化导致实际风险偏离需记录，不能倒算。

已有同symbol不加仓；同人工主题最多一个新增symbol，主题未知标unknown并单列集中度。不建设相关性连通图。费用、股息和现金机会成本口径固定。用户未提供预算时只展示价格计划，不推断真实资金或股数。

## 12. 评价：证明可赚、比较替代、解释漏报

### 12.1 先定义实验再看结果

manifest冻结：Universe及历史选择偏差、数据模式、结构/触发/执行/退出/事件/用户延迟/提醒预算/资金政策、参数hash、开发与锁定评价日期、主要指标、基线、成本、排除规则和seed。

S1首版为固定规则，没有待训练模型，不机械要求24个月“训练”。先将可用历史按时间划分开发段和未使用评价段，日期在首次运行前注册；不可反复看同一评价段调整规则。历史太短只做工程与前瞻shadow，不制造统计结论。

未来新增模型时再定义训练、验证、purge与walk-forward。当前仍按样本实际信号到最后退出/标签时间去掉跨开发/评价边界的重叠；不得按symbol随机切分。允许此前历史作特征warmup。

### 12.2 比较什么

固定主基线为同样执行/退出/成本/预算的S1无经济背景过滤版本；若当前评估对象正是S1，则主基线为同Universe的简单基准持有（冻结市场基准、100%或事前波动风险匹配两个版本），并报告现金对照。风险匹配仅用此前60日收益波动估计，不能用整个测试期事后调杠杆。

为避免实施agent选择有利基线：S1主检验固定使用100%市场基准持有，第一可操作时点按同数据模式买入、最后评价时点按同模式卖出并计成本；现金另报。波动匹配仅为诊断，目标权重=min(1,此前60日S1组合日收益标准差/此前60日基准日收益标准差)，每周首session在可操作窗口更新、计成本；缺warmup或基准波动为0时该诊断unknown。不能以风险匹配诊断通过替代主检验，也不能用该基线差异掩盖风险暴露不同。现金利息数据有则冻结源，缺失按0代理并显式披露，不能称真实现金收益已比较。

100%基准是直接投资的机会成本参照，不是风险完全相同的组合；不能仅因少量低暴露交易的总收益低于100%基准就断言其买点无盈利价值。相反，若没有选时/筛选增量，界面必须说明“有盈利依据，但未证明优于简单持有”，不能称最值得抓住或优于市场。具备同等风险/可用时间约束的比较尚未成立时，增量优势为unknown。

对背景过滤变体必须报告与S1的配对差异；绝对净期望同时独立检查。再增加以下诊断，不能每次挑最好击败的基线：
- 保留/修正后的旧系统，采用同一可比较执行政策，无法映射者只比较信号语义。
- 等提醒数量的随机/固定顺序选择，使用固定seed与相同资格/时间池。
- 完整S1与各单条件变体的全机会、不限资金结果，以及受资金/提醒预算约束结果。

不在首期实现没有明确仓位/退出定义的“等风险相对强弱轮动”基线。所有基线都必须像待测策略一样能独立运行，缺市场基准数据则相关结论unknown。

### 12.3 结果账本和漏报对照

每次真实trigger以固定政策跟踪1/2/5/10/20session价格标签，另存完整执行政策交易结果。MFE/MAE只从参考时刻之后计算；路径不明为ambiguous，停牌/退市/缺失为censored，成熟前为pending。用于跨政策评价的R固定为发送前计划风险，不受之后不利成交改变：Q1为(Q0.ask-S)×预定数量，M1为(观察close-S)×预定数量，D1为(U-S)×预定数量；发送前R必须>0。净R=净P&L/该固定分母。fill>S时可以另显示实际初始风险，但不替换主指标；fill<=S时也保留净P&L和计划R，不能因分母无效删掉最不利的交易。已知stop不保证损失上限。

扫描全池的固定时点对照用于诊断漏报：预注册每天10:00 ET，按相同15分钟延迟与可得执行数据，使用入场价减1 ATR的stop、20日时间退出，生成统一机会标签。该对照只是研究定义，不是“所有真实好机会”的真值，也不混作S1收益。

统计此定义下被规则拒绝却后续盈利的案例与收益贡献、被数据缺失挡住的案例、提醒预算挡住的案例。只有日线时使用独立daily_proxy网格，不能给盘中召回率。跨日重叠案例按同symbol事件段归组；覆盖率指标不当独立交易收益相加。

### 12.4 核心指标

1. 15分钟用户响应主模式的净期望R、净现金收益、组合净收益与现金机会成本。
2. 相对预注册主基线的配对日期净增量，风险/时间在场一并展示。
3. 提醒到成交比例、执行后价格延伸、1/5/15/30分钟响应敏感性。
4. 最大回撤、gap损失、成本压力、资金占用、盈利集中来源。
5. 每次提醒的有效收益与无效提醒数；漏掉的盈利贡献与原因。
6. 数据覆盖、退出假设、实际或模拟投递/成交来源。

胜率只是辅助。风险中性的“后来碰到目标”概率不替代真实退出政策净收益。少数大赢家贡献主要收益可以是策略特征；必须检查其数据、可执行性和独立重现，不以删掉最好5天后亏损为自动否决条件。

### 12.5 证据与发布

两条轴：
- 工程：可重放/时点正确/能部署。
- 收益证据：未验证/初步正向/支持当前使用模式/失效或不确定。

只有同时满足以下条件才把该版本标为“支持当前使用模式”：
- 主响应模式、主成本档的成本后净期望置信下界>0；计入现金机会成本的组合结果为正。
- 相对主基线的主要增量、风险/资金占用与可用时间差异必须报告，作为独立的selection_advantage结论。单纯依赖市场上涨未显示增量时，只能说明绝对盈利，不能宣称有额外选时优势。只有增量也经独立评价支持，才允许“优先于简单替代”的产品措辞或替换已有基线策略。
- 同一政策在高成本档点估计仍正，15分钟响应成立；只在1分钟成立时限制适用模式。
- 已审计关键盈利事件的数据/报价/时间与退出；未对不可观察或退市样本选择性删损。
- 结果来自未用于选参的数据，并有前瞻shadow核对提醒、延迟、取消、fill假设。
- 不确定性、背景覆盖和集中度公开；范围外不继承资格。

样本数、独立entry日期、覆盖月份、重叠交易和可重采样时间块数必须报告，不再用“100次+250天”充当自动认证。若收益几乎只来自一个独立事件，或只有极少可重采样时间块，标event_concentrated/unresolved，不输出精确置信声明。

统计协议初版：对所有symbol同步的日期块bootstrap，预注册20session块长、10/40敏感性、5000次、固定seed；对per-trade净R按entry日期成块并保留完整trade outcome，同期组合收益同时按日块评价。主要门槛看保守敏感性结果；若40日划分少于10个有效时间块则不自动授予支持资格，只报告点估计和不充分证据。这个工程限制是可审计的保守政策，不是收益保证。

单侧95%下界与双侧区间分开标注。多个变体时主假设预先唯一指定，其余探索性；正式多假设晋级需另固定校正方法，首版不要求agent自行发明Holm的p值计算。已经查看的holdout不得重用为下一版本“独立”证据。

没有足够历史并不阻止提供明确标注的研究计划，也不阻止修复错误；它阻止的是把未经验证的信号包装成有盈利依据的买入指导。统计方法的必要性可参考[回测过拟合原始研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)，本项目具体门槛不冒充论文结论。

## 13. 最小工程设计

### 13.1 首个离线版本

在现有Dataset上运行纯Python模块即可：
```text
buy_opportunities/contracts.py  # 类型、枚举、价格/时间约束
buy_opportunities/evidence.py   # 冻结输入与revision适配
buy_opportunities/scanner.py    # 全池扫描和拒绝原因
buy_opportunities/breakout.py   # S1结构与穿越事件
buy_opportunities/entry.py      # 提醒有效性、响应与订单意图
research/buy_execution.py       # Q1/M1/D1、退出、paper组合
research/buy_evaluation.py      # 结果、基线、消融、coverage
```

在线纯策略不得import未来结果模块。先使用现有数据库只读入口，新增不可变JSONL实验文件与manifest/结果摘要；临时文件原子写后校验hash，已完成实验不可覆写，研究run在主库可先只保存一条引用记录。无需提前建完整REST平台。

### 13.2 最小契约

- scan：scan_id、pool_version、knowledge_at、symbol、source_manifest、eligibility_by_dimension、features、rejection_codes。
- setup：setup_id、fingerprint、stream、symbol、family/parameter hash、origin、L/S/A/U、price_basis、valid_sessions、status。
- trigger：trigger_id、setup_id、kind、previous/current观察引用、occurred_at、known_at、freshness、extension_status。
- entry_intent：intent_id、trigger_id、user_policy、created/delivered/ready/recheck/sent/expired timestamps、Q0引用、limit、预先确定quantity、status/reason。
- execution/outcome：policy hash、source_mode、订单/成交/退出时间与证据、gross/net/cost/R、label horizon/coverage/censor原因。
- assessment：manifest hash、主要指标/基线/置信方法、适用模式、结论与限制。

价格有限且>0，S<L<=U；金额用稳定精度；UTC保存并附交易所时区；hash包含所有影响结果的规则与数据，排除随机显示ID。source manifest引用旧Dataset与revision，不复制整个行情平台。

### 13.3 取得第一轮结果后才做线上持久化

最少新增：scans、setups、triggers、entry_intents、opportunity_events及experiment_refs；名称可按现有仓库惯例调整。事件日志不可变，当前head可重建。结果标签先留研究存储；无业务需要不再单独建一套复杂assessment/关联表。

幂等键为输入证据hash+政策+对象身份；并发更新用唯一约束/CAS。标签成熟不占setup active key；新知识evaluation可更新当前eligibility，旧bar回放不能倒退行情游标。组关联在manifest保存；同一经济trigger跨组只计一次。

最小API只提供扫描/有效计划/单机会历史读取、模拟响应记录和实验结果读取。计算由现有Observation及必要盘中子评价服务触发。对外执行、定时运行、渠道推送启用独立记录，不因新增读取接口就自动开启。

### 13.4 迁移

旧投影和新版本并行；feature flag默认off。先offline/replay，再in-app shadow，再按审查结果切换研究入口。新方案未通过收益验证时保留“触发待验证”。回退切回旧读路径并停新评价，保留事实，不清库、不覆盖历史。

CONTEXT.md在批准并实际实施后更新，本提案不改写当前系统事实。首期不更改远端AI Workflow Binding。

## 14. 后续功能的进入条件
